# Hard rules — always loaded

Violating any of these produces code that is wrong even when it runs. These are
about the *code*, and carry over from upstream unchanged. Path names are this
repo's (`Core/`, not `Py4GWCoreLib/`).

## Persistence jail — no exceptions

Every file that touches disk goes through one of two classes:

- **INI / flat config → `Settings`** (`Core/py4gwcorelib_src/Settings.py`)
- **JSON / structured data → `JsonFactory`** (`Core/py4gwcorelib_src/JsonFactory.py`)

**Forbidden in project code** — not discouraged, forbidden: `open()` for
config/data, `json.load`/`json.dump`, `configparser`, `pickle`, `codecs.open`,
`pathlib.read_text`/`write_text` for persistence, `shutil` copies of config, and
any hand-rolled atomic-write / lock-file / directory-enumeration machinery. The
native side already does atomic writes, cross-process locking, and autosave.

No IPC through files — use `GLOBAL_CACHE.ShMem`. Never read another account's
file; shared data goes in `global` scope. Scope is `"account"` or `"global"`
only — `"root"` raises. `Py4GW.ini` is reached solely via `Settings.py4gw_ini()`.

**If `Settings`/`JsonFactory` lack something you need, STOP and tell the user**
so it can be added to the class or to the native project. Do not work around a
gap with a raw handler. Sanctioned exceptions: `Core/database_src/DBMgr.py`
(sqlite), and non-injected processes that physically cannot load the embedded
modules (external launcher, bridge/MCP stack), and `tools/` — which runs from a
plain interpreter, never inside the client.

## Use Reforged native names, not legacy GWCA ones

`Py2DRenderer`→`PyDXOverlay`, `PyCombatEvents`→`PyAgentEvents`,
`Py4GW.Console.*`→`PySystem.Console.*`, `Py4GW.Game.*`→`PySystem`/`PyGameThread`,
`Point2D`/`Point3D`→`Vec2f`/`Vec3f`, `PyScanCodeKeystroke`→`PyKeyHandler`.
`PyPointers` is retired. Reforged classes favor getter methods over data fields.

`Core.ImGui` is the single ImGui wrapper. The `ImGuiRuntime` facade rebuild was
abandoned and deleted; `docs/ImGui_Facade_Migration_Plan.md` is dead.

## Import constraints that break startup

- `HeroAI/follow/__init__.py` exports nothing **on purpose**. Import exact
  submodules (`HeroAI.follow.leader_publish`), never `HeroAI.follow`.
- `Core/GlobalCache/SharedMemory.py` imports `HeroAI.follow.leader_publish`
  directly and is startup-sensitive. Do not broaden it to a package-root import.
- `import Core` is **not** neutral: it appends system site-packages, redirects
  `sys.stdout`/`sys.stderr` into the Py4GW console, and eagerly pulls **241
  modules including 17 from `HeroAI`**. Prefer module-specific imports when
  debugging startup or import side effects. Reducing that closure is tracked in
  `docs/tier_map_and_separation_plan.md`.

## Tier 0 is a binary you consume

`Py4GW.dll` is built by a separate C++ project that is **not present in this
workspace**. You cannot rebuild or inspect it here. `stubs/` is your only
contract with it — treat a stub mismatch as the signal that the DLL moved.

## Toolchain

- **Interpreter: 3.13.0, 32-bit** is the injected target. There is no `.venv` in
  this repo yet; the sibling `Py4GW_Reforged/.venv/Scripts/python.exe` works for
  running `tools/`. Bare `python` is 3.11 in PowerShell (it cannot parse 3.12+
  nested-quote f-strings) and is **not on PATH at all in Bash**, along with `py`.
- **Bash tool** is Git Bash, rooted at the repo. Use relative paths.
- **PowerShell is 5.1**: no `&&`, no `||`, no ternary. Don't put `git` in a
  pipeline — use Bash for git. Long file lists overflow the command line; use
  `compileall.compile_dir` rather than `py -m py_compile @files`.
- **Spaces and `&` are everywhere in filenames** (`dev/reference/Wick Divinus
  bots/`). Unquoted shell loops silently truncate — use `find -print0` or quote
  every expansion. A module whose filename contains a space **cannot be
  imported**; shared code must live in an importable sibling.

## Formatting

Black `line-length = 120`, `skip-string-normalization = true` (keep single quotes
where present), isort `force_single_line = true`. There is no CI and no pytest
config — verify with targeted scripts, never assume a global test command exists.

## Navigation

`.claude/LINE_INDEX.md` is an auto-generated symbol index of every `.py` in the
tree (`L<line> <signature>`, grouped by file), regenerated by git hooks on
commit/checkout/merge/rebase. **Grep it first** — one search against one file
beats ripgrep across ~1,700 files.
